# E3 完成摘要

任务编号：E3  
完成内容：设计配置与密钥管理模块（M02），覆盖配置源与优先级、AppConfig 结构、SecretRef、配置文件格式、.env.local 加载、密钥脱敏、配置校验、配置诊断、Windows 编码处理、模块接口、异常降级、测试策略。  
产出文件：docs/25-配置与密钥管理设计.md

关键决定：
- 配置源优先级：CLI > 环境变量（含 CI Secrets）> .env.local > spring-review.yaml / .spring-review.yaml > 默认值。
- 覆盖规则：标量高优先级非空覆盖；布尔 CLI 出现即生效；列表 CLI 出现整体替换；路径相对 review.repoRoot；空环境变量与 YAML null 视为未设置。
- AppConfig 只承载 E2 冻结配置项，按 review / rules / schema / output / llm / static / exit / logging 组织；offline / validate / configPath 作为运行控制；密钥不进入 AppConfig。
- 配置来源映射：CLI 与环境变量映射到 AppConfig；CI Secrets 按环境变量参与合并，不单独提高优先级；GITHUB_ACTIONS 仅作 CI 环境标识。
- 密钥脱敏：必须脱敏 `*_API_KEY`、`*_TOKEN`、`*_SECRET`、Authorization、Cookie、私钥；日志、诊断、报告、异常栈、归档中统一为 `***`；SecretRef 只暴露 name / provider / source / envVarName / present / redactedValue，禁止打印全量环境变量。

未决问题：
- `llm.provider` 默认值与 `baseUrl/model` 最终默认值是否固定为 DeepSeek。
- `offline`、`validate` 是否进入 `AppConfig`，或仅作为运行控制由 `ReviewRequest` 传递。
- `--no-validate` 是否只影响报告校验，还是也影响规则/Schema 校验。
- `.env.local` 是否只搜索 `repoRoot`，还是支持向上查找。
- CI Secrets 识别是否仅依赖 `GITHUB_ACTIONS`，还是支持通用 CI 环境变量。
- 脱敏是否允许显示最后 4 位；当前设计固定 `***`。
- Java 环境下密钥临时缓冲清理的可行边界。
- `review.mode`、`exit.failOn` 的合法枚举值最终冻结。

下一个任务建议：
进入 E4：范围收集设计（对应 E2 模块 M04/M05/M06）。
