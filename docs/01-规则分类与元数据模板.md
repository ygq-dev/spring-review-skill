## 1. 设计原则

1. **只读审查**：规则仅用于检测与报告，不修改代码、不提交、不自动修复。
2. **来源可追溯**：每条规则必须标注来源，禁止编造规范。
3. **机器可解析**：规则元数据为 JSON/YAML 可表达结构，字段可校验，为 A5 的 JSON Schema 做准备。
4. **分类可扩展**：一级、二级分类采用注册制，编码不写死，允许后续新增。
5. **枚举封闭**：严重级别、置信度、检测方式、来源类型、状态等必须使用明确枚举值。
6. **规则独立版本**：规则库、规则元数据模板、JSON Schema、来源、工具版本均语义化版本。
7. **覆盖优先**：MVP 规则覆盖至少 8 类问题，第一版优先 Java 17+、Spring Boot 3.x。
8. **正反例成对**：每条规则必须提供正例与反例，最小化、可独立理解。
9. **工具解耦**：规则元数据不绑定具体实现，允许通过 `tool` 与 `tool_rule_id` 映射到 Checkstyle、PMD、ArchUnit、SpotBugs、JGit 或自定义引擎。
10. **可废弃不复用**：废弃规则保留编号与版本历史，状态标记为 `DEPRECATED`，编号不复用。

## 2. 规则分类体系

### 2.1 一级分类

一级分类编码为 2–4 位大写字母，全局唯一，采用注册制。新增一级分类必须在分类注册表中登记，不得与现有编码冲突。

### 2.2 二级分类

二级分类编码为 2 位数字，格式为 <两位数字>，例如 01、02。

二级分类在所属一级分类下从 `01` 开始递增，范围 `01`–`99`，在所属一级分类内唯一。  
二级分类名称、说明、状态在分类注册表中维护。新增二级分类需登记，不得与同属一级下的现有编码冲突。

### 2.3 分类编码规则

1. 一级分类码：`[A-Z]{2,4}`，全局唯一，注册制。
2. 二级分类码：`[0-9]{2}`，范围 `01`–`99`，在所属一级分类下唯一。
3. 分类路径：<一级分类码>-<二级分类码>，例如 AR-01，仅用于展示和文档引用。
4. 规则编号：`SRS-<一级分类码>-<二级分类码>-<规则序号>`，例如 `SRS-AR-01-001`。
5. 扩展规则：
   - 新增一级分类必须登记，编码不得与现有冲突。
   - 新增二级分类必须登记，编码在同属一级下不得冲突。
   - 分类可标记为 `DEPRECATED`，但不删除、不复用编码。
6. 规则分类变更时，`rule_id` 保持不变，更新 `category_l1`、`category_l2`，并在 `change_log` 中说明。

## 3. 规则元数据模板

### 3.1 标识与分类

| 字段名        | 类型          | 必填 | 取值范围                                             | 说明                              |
| ------------- | ------------- | ---- | ---------------------------------------------------- | --------------------------------- |
| `rule_id`     | string        | 是   | `SRS-[A-Z]{2,4}-[0-9]{2}-[0-9]{3}`                   | 全局唯一规则编号，格式见第 7 章。 |
| `name`        | string        | 是   | 1–120 字符                                           | 规则名称，简短明确。              |
| `description` | string        | 是   | 1–2000 字符                                          | 规则描述，说明检测目标与原因。    |
| `category_l1` | string        | 是   | 已注册一级分类码                                     | 一级分类编码。                    |
| `category_l2` | string        | 是   | `[0-9]{2}`                                           | 二级分类编码，在所属一级下唯一。  |
| `tags`        | array<string> | 否   | 每项 1–32 字符                                       | 标签，用于检索与分组。            |
| `status`      | enum          | 是   | `DRAFT`、`REVIEW`、`ACTIVE`、`DEPRECATED`、`REMOVED` | 规则生命周期状态。                |

### 3.2 严重与检测

| 字段名             | 类型    | 必填 | 取值范围                                                     | 说明                       |
| ------------------ | ------- | ---- | ------------------------------------------------------------ | -------------------------- |
| `severity`         | enum    | 是   | `BLOCKER`、`CRITICAL`、`MAJOR`、`MINOR`、`INFO`              | 严重级别，定义见第 4 章。  |
| `confidence`       | enum    | 是   | `HIGH`、`MEDIUM`、`LOW`                                      | 置信度，定义见第 5 章。    |
| `detection_method` | enum    | 是   | `STATIC_ANALYSIS`、`AST`、`ARCH_TEST`、`RULE_ENGINE`、`REGEX`、`HEURISTIC`、`HYBRID`、`MANUAL` | 检测方式，定义见第 6 章。  |
| `tool`             | enum    | 是   | `CHECKSTYLE`、`PMD`、`ARCHUNIT`、`SPOTBUGS`、`CUSTOM`        | 主要检测工具。             |
| `tool_rule_id`     | string  | 否   | 工具原生规则 ID                                              | 与工具规则映射时使用。     |
| `parameters`       | object  | 否   | 键值对                                                       | 规则参数，如阈值、白名单。 |
| `enabled`          | boolean | 是   | `true`、`false`                                              | 是否启用。                 |

### 3.3 适用范围

| 字段名                           | 类型          | 必填 | 取值范围                                                     | 说明                   |
| -------------------------------- | ------------- | ---- | ------------------------------------------------------------ | ---------------------- |
| `applies_to`                     | object        | 是   | 见下方子字段                                                 | 规则适用范围。         |
| `applies_to.java_version`        | string        | 是   | 如 `17+`、`21+`                                              | Java 版本范围。        |
| `applies_to.spring_boot_version` | string        | 是   | 如 `3.x`                                                     | Spring Boot 版本范围。 |
| `applies_to.build_tool`          | array<string> | 是   | `maven`、`gradle`                                            | 适用构建工具。         |
| `applies_to.module_type`         | array<string> | 是   | `web`、`api`、`data`、`security`、`batch`、`cloud`、`test`、`all` | 适用模块类型。         |
| `applies_to.framework`           | array<string> | 否   | `spring-mvc`、`spring-data`、`spring-security`、`spring-batch`、`spring-cloud` | 适用框架。             |
| `applies_to.exclude`             | array<string> | 否   | 路径或模块模式                                               | 排除范围。             |

### 3.4 内容与示例

| 字段名                 | 类型   | 必填 | 取值范围    | 说明                           |
| ---------------------- | ------ | ---- | ----------- | ------------------------------ |
| `message`              | string | 是   | 1–500 字符  | 检出消息模板，支持占位符。     |
| `remediation`          | string | 是   | 1–2000 字符 | 修复建议，只读审查不自动修复。 |
| `positive_example`     | string | 是   | 1–5000 字符 | 正例，符合规则。               |
| `negative_example`     | string | 是   | 1–5000 字符 | 反例，违反规则。               |
| `false_positive_notes` | string | 否   | 1–1000 字符 | 误报说明与豁免条件。           |

### 3.5 来源与版本

| 字段名              | 类型          | 必填 | 取值范围                                                     | 说明                                        |
| ------------------- | ------------- | ---- | ------------------------------------------------------------ | ------------------------------------------- |
| `sources`           | array<object> | 是   | 至少 1 项                                                    | 来源列表，每项含 `type`、`ref`、`version`。 |
| `sources[].type`    | enum          | 是   | `OFFICIAL_SPEC`、`FRAMEWORK_DOC`、`BOOK`、`COMMUNITY`、`CVE`、`INTERNAL_EXPERIENCE`、`TOOL_RULE` | 来源类型，见第 9 章。                       |
| `sources[].ref`     | string        | 是   | URL 或文档编号+章节                                          | 来源引用。                                  |
| `sources[].version` | string        | 是   | 来源版本                                                     | 必须锁定。                                  |
| `sources[].note`    | string        | 否   | 1–500 字符                                                   | 备注。                                      |
| `rule_version`      | string        | 是   | 语义化版本 `MAJOR.MINOR.PATCH`                               | 规则自身版本。                              |
| `metadata_version`  | string        | 是   | 语义化版本                                                   | 元数据模板版本。                            |
| `schema_version`    | string        | 是   | 语义化版本                                                   | JSON Schema 版本。                          |

### 3.6 生命周期与测试

| 字段名          | 类型          | 必填 | 取值范围                                                     | 说明                                                         |
| --------------- | ------------- | ---- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `owner`         | string        | 是   | 1–64 字符                                                    | 规则负责人或团队。                                           |
| `created_at`    | string        | 是   | ISO 8601 日期                                                | 创建日期。                                                   |
| `updated_at`    | string        | 是   | ISO 8601 日期                                                | 更新日期。                                                   |
| `deprecated_at` | string        | 否   | ISO 8601 日期                                                | 规则废弃日期，status=DEPRECATED 或 REMOVED 时必填            |
| `removed_at`    | string        | 否   | ISO 8601 日期                                                | 规则移除日期，status=REMOVED 时必填                          |
| `change_log`    | array<object> | 否   | 每项含 `version`、`date`、`description`                      | 变更记录。                                                   |
| `test_cases`    | array<string> | 否   | `^TC-(AR\|CF\|DI\|WEB\|DAO\|SEC\|CON\|PERF\|OBS\|EXC\|RES\|TEST\|BUILD\|STYLE\|NULL\|I18N\|MIG\|CLOUD)-\d{3}$` | 测试用例 ID 数组，ID 格式 TC-<一级分类码>-<三位序号>，需存在于 tests/cases/index.json |
| `coverage`      | string        | 否   | 1–500 字符                                                   | 覆盖率或验证说明。                                           |

条件约束：

- status = DEPRECATED 时，deprecated_at 必填。
- status = REMOVED 时，deprecated_at、removed_at 必填。
- deprecated_at 出现时，status 必须为 DEPRECATED 或 REMOVED。
- removed_at 出现时，status 必须为 REMOVED。

## 4. 严重级别定义

| 枚举值     | 名称 | 定义                                               | 处理建议       | 是否阻断合并 |
| ---------- | ---- | -------------------------------------------------- | -------------- | ------------ |
| `BLOCKER`  | 阻断 | 安全漏洞、数据丢失、生产不可用、严重合规问题       | 必须立即修复   | 是           |
| `CRITICAL` | 严重 | 高概率导致故障、安全风险、事务失效、资源泄漏       | 合并前必须修复 | 是           |
| `MAJOR`    | 主要 | 违反框架最佳实践，可能导致维护、性能、可观测性问题 | 建议合并前修复 | 否           |
| `MINOR`    | 次要 | 代码风格、可读性、命名、轻微重复                   | 可后续修复     | 否           |
| `INFO`     | 提示 | 优化建议，不强制                                   | 仅提示         | 否           |

## 5. 置信度定义

| 枚举值   | 定义                                   | 误报预期 | 处理方式                     |
| -------- | -------------------------------------- | -------- | ---------------------------- |
| `HIGH`   | 规则确定性强，工具或语义分析可直接判定 | ≤5%      | 可直接报告，默认启用         |
| `MEDIUM` | 规则依赖上下文或启发式判断             | ≤20%     | 报告时标注需人工确认         |
| `LOW`    | 规则为弱启发式，误报可能较高           | >20%     | 默认关闭或仅提示，需人工审查 |

## 6. 检测方式定义

| 枚举值            | 定义                 | 适用工具                  | 说明                     |
| ----------------- | -------------------- | ------------------------- | ------------------------ |
| `STATIC_ANALYSIS` | 基于静态分析工具规则 | Checkstyle、PMD、SpotBugs | 工具原生或扩展规则。     |
| `AST`             | 基于抽象语法树分析   | PMD、自定义解析器         | 精确匹配语法结构。       |
| `ARCH_TEST`       | 基于架构测试         | ArchUnit                  | 分层、依赖、包结构。     |
| `RULE_ENGINE`     | 基于自定义规则引擎   | CUSTOM                    | 可组合多条件。           |
| `REGEX`           | 基于正则表达式       | CUSTOM、Checkstyle        | 适用于文本模式。         |
| `HEURISTIC`       | 启发式/模式匹配      | CUSTOM                    | 上下文弱，需标注置信度。 |
| `HYBRID`          | 组合多种方式         | 多工具                    | 提高准确率。             |
| `MANUAL`          | 人工审查             | 人工                      | 仅用于描述，不自动检测。 |

## 7. 规则编号规则

1. 格式：`SRS-<一级分类码>-<二级分类码>-<规则序号>`。
2. 一级分类码：`[A-Z]{2,4}`，注册制，全局唯一。
3. 二级分类码：`[0-9]{2}`，范围 `01`–`99`，在所属一级下唯一。
4. 规则序号：`[0-9]{3}`，范围 `001`–`999`，在所属二级分类下递增。
5. 全局唯一，一经分配不复用。
6. 规则分类变更时，`rule_id` 不变，更新 `category_l1`、`category_l2`，并写入 `change_log`。
7. 废弃规则保留编号，`status` 置为 `DEPRECATED`，不得删除。
8. 示例：`SRS-AR-01-001`、`SRS-SEC-01-001`、`SRS-DAO-01-001`。

## 8. 正例与反例编写规范

1. 成对出现：每条规则必须同时提供 `positive_example` 与 `negative_example`。
2. 最小化：只保留触发或说明规则所需的最小上下文，避免完整项目。
3. 可独立理解：正例、反例应能脱离原项目理解。
4. 标注上下文：注明语言、版本、框架、模块类型。
5. 禁止敏感信息：不得包含真实密码、密钥、个人信息、生产数据。
6. 反例应触发规则：反例必须能命中检测条件。
7. 正例不应触发规则：正例必须符合规则。
8. 关键行标注：可使用注释或文字说明关键行。
9. 无法代码化时：可使用伪代码、配置片段或文字描述。
10. 字段格式：`positive_example`、`negative_example` 为字符串，可包含 Markdown 代码块或纯文本。

## 9. 来源标注规范

1. 来源必须可追溯，禁止编造规范。
2. `sources` 为数组，至少 1 项。
3. 每项包含：
   - `type`：来源类型，枚举见下。
   - `ref`：URL 或文档编号 + 章节。
   - `version`：来源版本，必须锁定。
   - `note`：可选备注。
4. 来源类型枚举：
   - `OFFICIAL_SPEC`：官方规范，如 JSR、Java 语言规范、Jakarta 规范。
   - `FRAMEWORK_DOC`：框架官方文档，如 Spring Framework、Spring Boot。
   - `BOOK`：正式出版书籍。
   - `COMMUNITY`：社区文章、博客、Wiki。
   - `CVE`：安全公告与漏洞库。
   - `INTERNAL_EXPERIENCE`：内部经验，需至少两人评审。
   - `TOOL_RULE`：工具原生规则文档。
5. 多个来源按可信度排序：官方规范 > 框架文档 > 书籍 > CVE > 工具规则 > 社区 > 内部经验。
6. 来源失效时，规则应更新来源或标记为 `DEPRECATED`。
7. 若来源本身无版本号，version 填 N/A，但 ref 必须精确到 URL 或文档章节，并在 note 中说明访问日期。

## 10. 版本标注规范

1. 语义化版本：`MAJOR.MINOR.PATCH`。
2. 规则版本 `rule_version`：每条规则独立版本，修改规则时递增。
3. 规则库版本：整体规则集合版本，由规则库清单维护。
4. 元数据模板版本 `metadata_version`：本模板版本。
5. JSON Schema 版本 `schema_version`：对应 JSON Schema 版本。
6. 来源版本：`sources[].version` 必须锁定。
7. 工具版本：Checkstyle、PMD、ArchUnit、SpotBugs、JGit 等版本需锁定。
8. 废弃规则保留编号、版本历史与 `change_log`。
9. 版本变更必须写入 `change_log`，包含 `version`、`date`、`description`。

metadata_version 与 schema_version 独立演进，各自语义化版本；不要求同步递增，不互相派生。
