# 23-技术选型

> 修订说明：按本机已有环境调整，优先复用已安装版本；Spring Boot 采用你已验证过的 3.5.13；Java 采用本机 17.0.3.1；Maven 采用本机 3.8.9。  
> 范围：Spring Review Skill 工具自身技术栈。只读审查；不修改代码、不提交、不训练模型。  
> 约束：不改 A5 规则元数据结构，不改 A6 报告结构；不写代码；不做 E2 模块设计与接口契约。  
> 目标：Java 17+/Spring Boot 3.x；Maven/Gradle 目标项目；git diff 或指定模块；输出 Markdown + JSON；模型调用可关闭。

## 1. 选型原则

1. **复用本机优先**：Java 17、Maven 3.8.9、MySQL 8.0.28 已安装；不引入需要额外安装的运行时。
2. **成熟稳定优先**：优先 LTS、Spring Boot 默认依赖、社区活跃且维护中的方案。
3. **只读与可关闭**：所有检查只读；模型调用必须可配置关闭，offline 模式可完整跑静态规则。
4. **最小依赖**：能由 Spring Boot BOM 管理的，不额外引入；MVP 不引入向量库、数据库、模板引擎。
5. **自动化友好**：CLI 退出码、JSON/Markdown 双输出、CI 可运行、密钥走环境变量。

## 3. 逐项决策

### 3.1 Java 版本

- 决策项：运行时与编译 Java 版本。
- 候选选项：Java 17 LTS（本机 17.0.3.1）；Java 21 LTS。
- 选定：Java 17 LTS。
- 版本号：17.0.3.1；建议后续可升到 Java 17 最新补丁，但本次不强制。
- 选择理由：本机已装；LTS；Spring Boot 3.5.13 支持；MVP 够用。
- 放弃其他选项理由：Java 21 需新装，MVP 无必须特性。
- 影响范围：CLI、规则执行、静态工具、测试、CI、打包。

### 3.2 Spring Boot 版本

- 决策项：Spring Boot 主版本。
- 候选选项：3.5.13；3.3.x；3.2.x。
- 选定：Spring Boot 3.5.13。
- 版本号：3.5.13。
- 选择理由：你已有项目经验；Java 17 兼容；生态成熟；依赖 BOM 稳定。
- 放弃其他选项理由：3.3.x、3.2.x 更旧，无必要降级。
- 影响范围：应用启动、配置、依赖管理、JSON/YAML/日志、测试。

### 3.3 构建工具

- 决策项：本工具构建工具；是否双支持目标项目构建。
- 候选选项：Maven 3.8.9（本机）；Gradle；Maven + Gradle 双构建。
- 选定：本工具 Maven 3.8.9；目标项目 Maven/Gradle 双识别，但不执行目标项目构建。
- 版本号：Maven 3.8.9；目标项目识别 Gradle 7.x/8.x。
- 选择理由：本机已装；Spring 生态默认；CI 稳定；只读审查不需要执行目标构建。
- 放弃其他选项理由：Gradle 本工具构建需额外学习/安装；双构建增加 CI 与发布复杂度。
- 影响范围：CI、依赖管理、项目扫描、规则触发条件。

### 3.4 CLI 框架

- 决策项：命令行入口框架。
- 候选选项：picocli；Spring Shell；纯 args。
- 选定：picocli。
- 版本号：4.7.6。
- 选择理由：轻量；子命令、参数校验、帮助、退出码完善；与 Spring Boot 集成简单；适合 CI。
- 放弃其他选项理由：Spring Shell 偏交互式，依赖重；纯 args 难维护、难测试。
- 影响范围：CLI 入口、命令解析、退出码、帮助文档。

### 3.5 模型调用方式

- 决策项：调用大模型的客户端方式。
- 候选选项：Spring AI；LangChain4j；直接 HTTP。
- 选定：直接 HTTP + 自有 `LlmClient` 抽象。
- 版本号：JDK 17 `HttpClient`；JSON 用 Jackson。
- 选择理由：可控、低依赖、多厂商兼容、易实现 offline 开关；不绑定快速演进的 AI 框架。
- 放弃其他选项理由：Spring AI 版本较新且与 Boot 版本耦合；LangChain4j 依赖多、抽象重。
- 影响范围：模型调用模块、配置、密钥、报告 `tool_runs`、offline 模式。

### 3.6 模型提供方

- 决策项：模型厂商与是否多厂商。
- 候选选项：单厂商 OpenAI；单厂商 DeepSeek；单厂商 Qwen；多厂商 OpenAI 兼容。
- 选定：多厂商，OpenAI 兼容协议；默认 DeepSeek，可切 OpenAI / Qwen。
- 版本号：OpenAI API v1；DeepSeek API v1；Qwen DashScope OpenAI 兼容模式。
- 选择理由：避免厂商锁定；DeepSeek 成本与中文友好；OpenAI 兼容接口统一配置。
- 放弃其他选项理由：单厂商锁定风险高；多套私有协议增加适配成本。
- 影响范围：配置项、密钥管理、prompt、成本控制、离线回退。

### 3.7 静态检查工具版本

- 决策项：Checkstyle、PMD、ArchUnit、SpotBugs 的采用与版本。
- 候选选项：全部默认启用；核心源码检查启用 + 字节码/架构检查可选；全部不启用。

- 选定：

- Checkstyle 10.17.0：采用。

- PMD 7.4.0：采用。

- SpotBugs 4.8.6：可选，MVP 默认关闭。

- ArchUnit 1.3.0：不纳入 MVP 运行时，仅保留规则示例/后续阶段。

- AR 类规则在 MVP 用 JavaParser 做包依赖分析，detection_method 采用 HYBRID；ArchUnit 留到增强阶段。SRS-AR-01-001、SRS-AR-02-001 的 tool 字段从 ARCHUNIT 改为 CUSTOM。

- 选择理由：Checkstyle/PMD 只读源码即可运行，适合 diff/module；SpotBugs 依赖编译产物，默认关闭避免副作用；ArchUnit 需要类加载上下文，延后。

- 放弃其他选项理由：全部默认启用会扩大权限、耗时与构建依赖；全部不启用则规则执行器过弱。

- 影响范围：规则执行器、tool_runs、报告证据、CI 耗时。

### 3.8 向量库

- 决策项：RAG 向量库是否引入。
- 候选选项：不引入；PgVector；Qdrant；Milvus；Elasticsearch。
- 选定：不引入。
- 版本号：N/A。
- 选择理由：MVP 规则、示例、测试均为结构化 YAML/JSON；文件路径与规则 ID 可满足检索；offline 优先。
- 放弃其他选项理由：向量库增加部署、依赖、密钥与运维成本，MVP 收益低。
- 影响范围：模型检索、部署、配置、后续 RAG 扩展。

### 3.9 JSON 库

- 决策项：JSON 序列化/反序列化库。
- 候选选项：Jackson；Gson；JSON-B；Moshi。
- 选定：Jackson。
- 版本号：由 Spring Boot 3.5.13 BOM 管理，不单独锁版本。
- 选择理由：Spring Boot 默认；Schema、报告、配置绑定成熟；与 YAML 模块统一。
- 放弃其他选项理由：Gson 功能与生态弱；JSON-B/Moshi 在 Spring 生态中优势不明显。
- 影响范围：报告输出、规则索引、配置、测试断言。

### 3.10 YAML 库

- 决策项：YAML 解析库。
- 候选选项：SnakeYAML；Jackson YAML；SnakeYAML Engine；手动解析。
- 选定：SnakeYAML + Jackson Dataformat YAML。
- 版本号：由 Spring Boot 3.5.13 BOM 管理，不单独锁版本。
- 选择理由：rules/<分类>.yaml 为多文档 YAML；SnakeYAML 支持成熟；Jackson 统一对象映射。
- 放弃其他选项理由：手动解析不可靠；SnakeYAML Engine API 变动大，暂无必要。
- 影响范围：规则加载、配置、index.json 生成、测试夹具。

### 3.11 日志框架

- 决策项：日志门面与实现。
- 候选选项：SLF4J + Logback；SLF4J + Log4j2；JUL。
- 选定：SLF4J + Logback。
- 版本号：由 Spring Boot 3.5.13 BOM 管理，不单独锁版本。
- 选择理由：Spring Boot 默认；成熟稳定；配置简单；CI 输出友好。
- 放弃其他选项理由：Log4j2 额外依赖且无必要；JUL 生态弱。
- 影响范围：CLI、工具运行、错误诊断、报告日志。

### 3.12 测试框架

- 决策项：单元/集成测试框架。
- 候选选项：JUnit 5 + AssertJ + Mockito；TestNG；Spock。
- 选定：JUnit 5 + AssertJ + Mockito。
- 版本号：由 Spring Boot 3.5.13 BOM 管理，不单独锁版本。
- 选择理由：Java 主流；Spring Boot 默认；55 个测试用例与夹具易迁移；断言可读。
- 放弃其他选项理由：TestNG 生态弱；Spock 引入 Groovy，偏离 Java 偏好。
- 影响范围：单元测试、集成测试、CI、夹具校验。

### 3.13 CI 平台

- 决策项：持续集成平台。
- 候选选项：GitHub Actions；GitLab CI；Jenkins；其他。
- 选定：GitHub Actions。
- 版本号：actions/checkout@v4；actions/setup-java@v4；Java 17。
- 选择理由：托管、矩阵构建、缓存成熟；开源协作友好；维护成本低。
- 放弃其他选项理由：GitLab CI 依赖仓库平台；Jenkins 自维护成本高。
- 影响范围：构建、测试、静态检查、报告工件、发布。

### 3.14 密钥管理方式

- 决策项：模型 API Key 等密钥管理。
- 候选选项：环境变量 + CI Secrets + 本地 .env.local；HashiCorp Vault；OS Keychain；明文配置文件。
- 选定：环境变量 + CI Secrets + 本地 .env.local。
- 版本号：N/A。
- 选择理由：简单、安全、跨平台；offline 模式无需密钥；CI 不落盘。
- 放弃其他选项理由：Vault 过重；OS Keychain 跨平台复杂；明文配置不安全。
- 影响范围：模型调用、CI、本地开发、offline 开关。

### 3.15 报告输出路径约定

- 决策项：reports/ 下组织方式。
- 候选选项：扁平 reports/；按 report_id 单层；latest + history。
- 选定：`reports/latest` + `reports/history/YYYY/MM/DD/<report_id>/`。
- 版本号：与 A6 `schema_version` 对齐。
- 选择理由：latest 便于人工查看；history 可追溯；CI 工件路径稳定；tool_runs 可拆分子文件。
- 放弃其他选项理由：扁平目录易冲突；仅 report_id 不便查找最新报告。
- 影响范围：ReportWriter、CLI 参数、CI artifacts、报告 schema 兼容。

建议结构：

```text
reports/
  latest/
    review-report.md
    review-report.json
    metrics.json
  history/
    YYYY/
      MM/
        DD/
          <report_id>/
            review-report.md
            review-report.json
            metrics.json
            tool_runs/
              checkstyle.json
              pmd.json
              spotbugs.json
            logs/
              review.log
```

## 5. 被放弃的候选及其理由汇总

| 候选                                        | 放弃理由                                             |
| ------------------------------------------- | ---------------------------------------------------- |
| Java 21                                     | 需新装，MVP 无必须特性                               |
| Spring Boot 3.3.x / 3.2.x                   | 比 3.5.13 更旧，无必要降级                           |
| Gradle 作为本工具构建                       | 本机已有 Maven 3.8.9，Spring 默认 Maven，CI 简单优先 |
| Maven + Gradle 双构建                       | 维护成本高，MVP 无必要                               |
| Spring Shell                                | 偏交互式，依赖重                                     |
| 纯 args CLI                                 | 子命令、校验、帮助、退出码维护差                     |
| Spring AI                                   | 版本较新，与 Boot 版本耦合                           |
| LangChain4j                                 | 依赖多，抽象重                                       |
| 单厂商模型                                  | 锁定风险高，切换成本大                               |
| 向量库 PgVector/Qdrant/Milvus/Elasticsearch | MVP 无 RAG 必要，部署与依赖成本高                    |
| Gson / JSON-B / Moshi                       | Spring 生态与功能不如 Jackson                        |
| SnakeYAML Engine                            | API 变动大，暂无必要                                 |
| Log4j2                                      | 额外依赖，无必要                                     |
| TestNG / Spock                              | 生态或语言偏好不匹配                                 |
| GitLab CI / Jenkins                         | 平台依赖或自维护成本高                               |
| Vault / OS Keychain                         | MVP 过重                                             |
| 扁平 reports/                               | 易冲突，不便追溯                                     |
| SpotBugs 默认启用                           | 依赖字节码，扩大权限与耗时                           |
| ArchUnit 纳入 MVP 运行时                    | 需要类加载上下文，延后                               |
| MySQL 作为 MVP 存储                         | 本机已装 8.0.28，但只读审查用文件系统足够            |
