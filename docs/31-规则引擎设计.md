# docs/31-规则引擎设计.md

状态：E9 设计候选；只读审查；不修改代码、不提交、不训练模型。  
对齐：E2 M12/M13、A2/A5/A6、E5/E6/E7/E8。  
约束：不新增 E3 未冻结配置字段；如需新增，走 E2 配置清单评审。不修改 A6 issue、summary、metrics 结构。

## 1. 设计原则

1. 只读与确定性优先：M12/M13 不修改源码、不提交、不训练；确定性规则不可关闭，LLM 语义规则可关闭。
2. 契约冻结：严格对齐 E2 M12/M13 接口、A2 元数据、A6 issue/summary/metrics；候选与最终报告分离。
3. 元数据驱动：规则执行方式由 `detection_method`、`confidence`、`severity`、`category`、`tool`、`applies_to`、`parameters` 决定。
4. 可降级与可观测：单规则、单文件、LLM、去重失败均局部降级并记录；空结果不致命但必须警告。
5. 稳定幂等：相同输入产生稳定排序、稳定 issue_id、稳定 fingerprint；LLM 部分在相同模型/参数/输入下尽量稳定，不承诺强幂等。

## 2. M12 规则匹配设计

### 2.1 match(SelectedRules, SourceBundle, ParsedSource, StaticAnalysisResult) -> List<IssueCandidate>

- 输入：
  - `SelectedRules`：已加载规则、选择原因、跳过项。
  - `SourceBundle`：待审源码单元与元数据。
  - `ParsedSource`：M09 产出，含 `sourceUnit`、`package`、`imports`、`classes`、`methods`、`dependencyGraph`、`parseErrors`。
  - `StaticAnalysisResult`：M10 产出，含 `ToolRun` 列表、`IssueCandidate` 列表。
- 输出：`List<IssueCandidate>`，仅候选，不直接进最终报告。
- 处理：
  - 按 `detection_method` 分组：`STATIC_ANALYSIS`、`AST`、`RULE_ENGINE`、`REGEX`、`HYBRID`。
  - 消费 M10 已产候选，执行 M09/M12 可执行的确定性规则。
  - 生成 `sourceTool`、`fingerprint`、`rawEvidence`、`tool_rule_id`。
- 异常契约：
  - 单规则失败：记录规则级错误，继续其他规则；不中断整体。
  - 单文件失败：记录文件级错误，继续其他文件；可标记 partial。
  - 输入缺失：对应规则跳过并记录 warning；不抛致命异常。
- 幂等性：相同输入、相同规则集、相同工具输出下，候选集合与 fingerprint 稳定。
- 线程安全：规则上下文只读；每个文件/规则独立执行；结果收集使用线程安全容器或分片合并。

### 2.2 semanticReview(...) -> List<IssueCandidate>

- 输入：同 `match`，但仅处理需要 LLM 语义分析的规则。
- 输出：`List<IssueCandidate>`，可为空。
- 处理：
  - 仅当规则元数据要求 LLM 或 HYBRID 含 LLM 组件，且 `LlmClient.enabled=true`、非 offline、规则 `enabled`、`applies_to` 命中时调用。
  - 构造 `LlmRequest`，解析 `LlmResponse`，映射为 `IssueCandidate`。
  - LLM 失败时返回已成功部分或空，并保留确定性规则结果。
- 异常契约：
  - LLM 不可用、超时、解析失败：记录模型调用错误；不抛致命异常。
  - 响应结构不合法：丢弃该条或降级为 LOW，并记录 warning。
- 幂等性：非强幂等；通过固定 temperature、固定 prompt、traceId 可追踪；可选缓存需 E3 评审。
- 线程安全：`LlmClient` 需线程安全；并发调用受控；每请求独立上下文。

### 2.3 confidenceOf(candidate) -> double

- 输入：`IssueCandidate`。
- 输出：double，内部数值映射：
  - `HIGH` → 0.9
  - `MEDIUM` → 0.6
  - `LOW` → 0.3
- 规则：
  - 优先使用候选 `confidence`；缺失时回退规则元数据 `confidence`；仍缺失按 `LOW`。
  - HYBRID 候选按组合证据计算，见第 5、10 节。
- 异常契约：未知候选返回 LOW 对应值并记录 warning。
- 幂等性：纯函数，无副作用。
- 线程安全：只读，线程安全。

## 3. 确定性规则执行

| detection_method | 数据来源                                          | 执行方式                                                     | 输出标记                           |
| ---------------- | ------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------- |
| STATIC_ANALYSIS  | M10 `StaticAnalysisResult`                        | 消费已有 `IssueCandidate`，保留 `tool_rule_id`、`rawEvidence` | `detection_method=STATIC_ANALYSIS` |
| AST              | M09 `ParsedSource`/`ParsedBundle`                 | 按规则 `applies_to` 匹配类、方法、导入、依赖图；AR 规则见第 5 节 | `detection_method=AST` 或 `HYBRID` |
| RULE_ENGINE      | `SelectedRules` + `SourceBundle` + `ParsedSource` | 自定义声明式规则，基于 `patterns`、`parameters`、符号/文本/AST 条件 | `detection_method=RULE_ENGINE`     |
| REGEX            | `SourceUnit.content` 或指定节点文本               | 按 `patterns` 正则匹配，偏移换算行号、列号，行列 >=1         | `detection_method=REGEX`           |
| HYBRID           | 组合上述来源                                      | 多检测器结果合并，证据合并，置信度按第 10 节合并             | `detection_method=HYBRID`          |

正则表达式必须在固定超时内执行（内部常量，如 1000ms），防止灾难性回溯；超时记录 warning 并跳过该规则。如需配置化，走 E2 配置清单评审。

确定性规则不可关闭；规则缺失、工具失败、解析失败时跳过并记录，不影响其他规则。

## 4. LLM 语义规则执行

- 何时调用：
  - 规则 `detection_method` 含 LLM 或 HYBRID 的 LLM 组件。
  - `LlmClient.enabled=true` 且非 offline。
  - 规则 `enabled`、`applies_to`、范围命中。
  - 静态与 AST 结果可作为上下文一并输入，减少误报。
- 构造 `LlmRequest`：
  - `provider`、`model`：来自 E8 配置与规则元数据，默认 DeepSeek。
  - `messages`：system 放规则 `prompt`、审查边界、输出 schema；user 放代码片段、AST 摘要、静态结果摘要。
  - `temperature`：低值；`maxTokens`：按规则或 E8 默认。
  - `responseFormat`：JSON；`timeout`：E8 默认；`traceId`：候选追踪。
- 解析 `LlmResponse`：
  - 仅接受结构化 JSON；校验字段。
  - 映射为 `IssueCandidate`：`rule_id`、`severity`、`confidence`、`detection_method`、`file`、`line`、`column`、`evidence`、`message`、`remediation`、`sourceTool`、`fingerprint`、`rawEvidence`、`tool_rule_id`。
  - LLM 未给可靠行列时，用片段锚点回定位；无法定位则丢弃或降级并记录；不修改 A6。
- offline 行为：
  - `semanticReview` 直接返回空；统计为 skipped；不报错误。
  - 确定性规则与静态结果继续。
- 与 A6 issue 关系：
  - LLM 只产 `IssueCandidate`；经 M13 去重、置信度合并、排序、字段映射后才成为 A6 `Issue`。
  - `detection_method` 不新增枚举；按 A2 使用 `HYBRID`、`HEURISTIC`、`RULE_ENGINE` 等已有值。

## 5. AR 规则的 HYBRID 判定

- AR-01：Controller 直接依赖 Repository
  - 从 M09 `dependencyGraph` 取类依赖边。
  - Controller 判定：`*Controller` 命名，或 `@Controller`、`@RestController` 元数据可用时确认。
  - Repository 判定：`*Repository` 命名，或 `@Repository` 元数据可用时确认。
  - 直接依赖：字段类型、构造参数、方法返回/参数、直接调用边。
  - 命中输出 `tool=CUSTOM`、`detection_method=HYBRID`。
  - 注解确认 + 直接边 → 高置信；仅命名 + 边 → 中置信；仅文本启发 → 低置信。
- AR-02：domain 依赖 Web/基础设施
  - domain 判定：包名/类名含 `domain`、`model`、`entity` 等，按规则元数据。
  - Web/基础设施判定：`controller`、`web`、`rest`、`repository`、`jdbc`、`jpa`、`kafka`、`redis` 等命名与包路径。
  - 依赖图边 + 规则元数据 `applies_to` + 命名启发式组合判定。
  - 命中输出 `tool=CUSTOM`、`detection_method=HYBRID`。
- 降级：
  - 依赖图缺失或解析失败时，降级为导入/文本启发式，`confidence=LOW`，记录 partial。
  - 不因 AR 失败中断其他规则。

## 7. Issue 结构（对齐 A6）

- 必填：`issue_id`、`rule_id`、`severity`、`confidence`、`detection_method`、`file`、`line`、`column`、`evidence`、`message`、`remediation`。
- 可选：`tool`、`tool_rule_id`、`test_case_id`、`snippet`、`fingerprint`、`first_seen_at`、`last_seen_at`、`issue_status`、`tags`。
- `issue_id`：`ISSUE-<8 位大写十六进制>`。
- `line`、`column`：整数，>=1。
- 枚举严格按 A6：severity、confidence、detection_method。

## 8. M13 问题汇总设计

### 8.1 aggregate(candidates, toolRuns) -> AggregatedIssues

- 输入：`List<IssueCandidate>`、`List<ToolRun>`。
- 输出：`AggregatedIssues`，包含：
  - 最终 `List<Issue>`；
  - E2 `Summary`；
  - A6 `summary` 映射；
  - A6 `metrics` 来源；
  - `toolRuns`、模型调用记录、警告、统计。
- 步骤：字段归一化 → 去重 → 置信度合并 → 排序 → 生成 issue_id → summarize。
- 异常：去重失败降级为简单排序并记录；不致命。
- 幂等：相同候选与工具运行输入，输出稳定。
- 线程安全：候选收集可并发，聚合阶段单线程或分片后合并。

### 8.2 dedupe(List<Issue>) -> List<Issue>

- 输入：`List<Issue>`。
- 输出：去重后 `List<Issue>`。
- 失败：降级为简单排序，记录 warning。
- 幂等：稳定。

### 8.3 sort(List<Issue>) -> List<Issue>

- 输入：`List<Issue>`。
- 输出：稳定排序后 `List<Issue>`。
- 幂等：稳定。

### 8.4 summarize(List<Issue>) -> Summary

- 输入：`List<Issue>`。
- 输出：E2 `Summary`：`total`、`bySeverity`、`byRule`、`byFile`、`byTool`、`blocking`。
- A6 映射见第 12 节。
- 空结果：返回全零 Summary，并产生 warning。

## 9. 去重算法

- 指纹定义：
  - 主指纹：规范化 `rule_id + file + 语义锚点 + line 窗口 + 规范化 message/evidence 摘要`。
  - `IssueCandidate.fingerprint` 由 M12 生成；M13 计算 `dedupe_key`。
- 跨工具去重：
  - `tool_rule_id` 映射到规范 `rule_id`。
  - 同 `file`、行号容差内、归一化 message/evidence 相似、severity/category 兼容时合并。
  - 保留来源列表，`tool` 记录最强来源或合并来源。
- 语义与静态重复：
  - 同文件、同符号/方法、同规则类别、关键实体相同 → 合并。
  - 保留最强证据与 remediation；弱证据降为 `rawEvidence` 或 tags。
- 行号漂移：
  - 优先使用 `diffChunks` 行映射。
  - 无映射时使用行号容差窗口；列号不参与强匹配。
  - 容差默认常量，若需配置走 E2 配置清单评审。
- 合并后：
  - `fingerprint` 取稳定主指纹。
  - `first_seen_at`、`last_seen_at` 仅在已有历史来源时保留，否则省略。

## 10. 置信度合并

内部数值：LOW=0.3，MEDIUM=0.6，HIGH=0.9。合并后映射回 A6 枚举。

| 情况                    | 合并结果                |
| ----------------------- | ----------------------- |
| HIGH + HIGH             | HIGH                    |
| HIGH + MEDIUM           | HIGH                    |
| HIGH + LOW              | HIGH                    |
| MEDIUM + MEDIUM，独立源 | HIGH                    |
| MEDIUM + LOW            | MEDIUM                  |
| LOW + LOW               | LOW                     |
| 同源重复                | 不提升                  |
| HYBRID 元数据指定       | 按元数据，但不超过 HIGH |

规则：强证据优先；多独立源一致可提升一档；弱证据保留为来源记录，不拉低强证据。

## 11. 排序策略

1. 一级：severity，`BLOCKER > CRITICAL > MAJOR > MINOR > INFO`。
2. 二级：confidence，`HIGH > MEDIUM > LOW`。
3. 三级：blocking 优先。
4. 四级：file 字典序升序。
5. 五级：line 升序、column 升序。
6. 六级：rule_id 字典序、issue_id 字典序。
7. 稳定排序；相同输入输出顺序一致。

## 12. Summary 生成

E2 Summary → A6 summary 映射：

| E2 Summary  | A6 summary             | 来源                                 |
| ----------- | ---------------------- | ------------------------------------ |
| total       | total_issues           | 最终 Issue 数                        |
| bySeverity  | by_severity            | 按 severity 枚举统计，属性名复用枚举 |
| byRule      | （仅 M13 内部）        | 按 rule_id 聚合，不写入 A6           |
| by_category | A6 summary.by_category | 由 byRule 按 category_l1 聚合生成    |
| byFile      | 报告层可用             | 文件维度                             |
| byTool      | 报告层可用             | 工具维度                             |
| blocking    | blocking               | 规则 blocking 或达到 failOn 的 issue |
| 无          | duration_ms            | M18/M13 计时注入                     |
| 无          | token_usage            | LLM 调用记录聚合                     |

- `by_category`：仅使用 A2 一级分类枚举；缺失时按 A2 默认，不新增枚举。
- `blocking`：按 A6 类型输出；M19 用 failOn 判定退出码 1。
- `token_usage`：累加所有 `LlmResponse.usage`；offline=0；失败调用若含 usage 则累加，否则计 0 并记录错误；结构严格复用 A6。
- A6 metrics 来源：
  - `total_files_scanned`：SourceBundle 文件数。
  - `total_lines_scanned`：SourceUnit.lines 汇总。
  - `duration_ms`：M12/M13 计时。
  - `tool_success_rate`：ToolRun 成功/总数。
  - `cache_hit_rate`、`llm_calls`、`by_severity`、`by_category`：按 A6 可选字段输出。

## 14. 异常与降级

- 单规则失败：记录规则级错误，继续其他规则。
- 单文件失败：记录文件级错误，继续其他文件；可标记 partial。
- LLM 调用失败：保留静态与确定性结果；语义规则部分为空；记录错误。
- 去重失败：降级为简单排序并记录 warning。
- 空结果：不致命；`total_issues=0`；必须警告。
- 确定性规则不可关闭；LLM 部分可关闭；offline 时语义规则跳过。

## 15. 性能与规模

- 大规则集：按 `detection_method`、`applies_to`、文件类型预分组；规则索引缓存。
- 大 SourceBundle：按文件分片、并发解析与匹配；合并阶段统一去重排序。
- 并发执行：M12 无共享可变状态；结果收集线程安全；M13 聚合可先分片去重再全局合并。
- LLM：并发限流、超时、重试由 E8 控制；失败不影响确定性结果。
- 内存：`rawEvidence` 可截断存储；大工具输出走 `rawOutputPath`。

## 16. 模块接口（对齐 E2 M12/M13 契约）

- M12：
  - `match(SelectedRules, SourceBundle, ParsedSource, StaticAnalysisResult) -> List<IssueCandidate>`
  - `semanticReview(...) -> List<IssueCandidate>`
  - `confidenceOf(candidate) -> double`
  - 依赖：M08、M09、M10、M11、M18；被 M03、M13 依赖。
  - 降级：LLM 可关闭；确定性规则不可关闭。
- M13：
  - `aggregate(candidates, toolRuns) -> AggregatedIssues`
  - `dedupe(List<Issue>) -> List<Issue>`
  - `sort(List<Issue>) -> List<Issue>`
  - `summarize(List<Issue>) -> Summary`
  - 依赖：M18；被 M03、M14 依赖。
  - 降级：不可关闭；去重失败降级为简单排序并记录。
