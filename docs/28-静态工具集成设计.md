# docs/28-静态工具集成设计.md

## 1. 设计原则
- 只读优先：不修改目标仓库、不执行构建、不写 `.class`/`build`/`target`。
- 统一适配：所有工具原始输出统一映射为 `ToolRun` 与 `IssueCandidate`。
- 失败隔离：单工具失败不阻断其他工具；失败记录状态并继续。
- 默认最小：Checkstyle/PMD 默认启用，SpotBugs 默认关闭；ARCHUNIT 不由 M10 运行。
- 临时产物外置：报告、原始输出、日志写入系统临时目录，不落目标仓库。

## 2. 静态工具总览
| 工具       | 版本    | 用途                                | 默认开关                         | 退出码影响                                            |
| ---------- | ------- | ----------------------------------- | -------------------------------- | ----------------------------------------------------- |
| Checkstyle | 10.17.0 | 编码规范、命名、导入、Javadoc、格式 | `static.checkstyle.enabled=true` | 不直接决定退出码；strict 下 FAILED/TIMEOUT 可致退出 5 |
| PMD        | 7.4.0   | 缺陷、坏味道、复杂度、未使用代码    | `static.pmd.enabled=true`        | 不直接决定退出码；strict 下 FAILED/TIMEOUT 可致退出 5 |
| SpotBugs   | 4.8.6   | 字节码缺陷、空指针、并发、资源      | `static.spotbugs.enabled=false`  | 默认不影响；启用且 strict 下失败可致退出 5            |

## 3. M10 接口设计
| 接口                                                      | 输入                                   | 输出                                                         | 异常                                          |
| --------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------ | --------------------------------------------- |
| `runAll(SourceBundle, AppConfig) -> StaticAnalysisResult` | SourceBundle、工具开关、工具配置、超时 | StaticAnalysisResult：`ToolRun[]`、`IssueCandidate[]`、metrics、errors | 不抛；内部捕获并写入结果                      |
| `runTool(Tool, SourceBundle) -> ToolRun`                  | Tool、SourceBundle                     | ToolRun，含 rawOutputPath、原始格式、issueCount              | 不抛；失败返回 FAILED/TIMEOUT/SKIPPED ToolRun |
| `adapt(rawOutput) -> List<IssueCandidate>`                | 原始输出路径、工具类型、格式           | IssueCandidate 列表                                          | 不抛；解析失败返回空列表并记录错误            |

依赖：M18 记录日志、耗时、trace、脱敏。被 M03、M12、M13 依赖。

## 4. 工具调用方式（只读）
- 调用策略：MVP 统一命令行调用，固定版本；库调用作为后续优化，不作为 MVP 必需。
- Checkstyle：命令行调用，XML 输出到临时目录。
- PMD：命令行调用，XML 输出到临时目录，禁用缓存写入。
- SpotBugs：命令行调用，XML 输出到临时目录；默认关闭。
- 输出格式：Checkstyle XML、PMD XML、SpotBugs XML；SARIF 仅作为可选中间适配，不作为主格式。
- 只读约束：命令工作目录为临时目录；输出路径、缓存路径均不指向目标仓库。

## 5. Checkstyle 集成细节
- 配置文件：内置 `config/checkstyle/srs-checkstyle.xml`，只读加载，不写目标仓库。
- 输出解析：解析 `<checkstyle><file><error line column severity message source>`。
- 规则映射：`source` → `rules/index.json` 中 `tool=CHECKSTYLE` 的 `tool_rule_id` → `SRS-* rule_id`。
- `tool_rule_id` 处理：保留原始 `source` 全限定名，大小写敏感，存入内部字段与 `rawEvidence`。
- severity 映射：规则元数据优先；否则 `error→MAJOR`、`warning→MINOR`、`info→INFO`。
- 默认：`confidence=HIGH`，`detection_method=STATIC_ANALYSIS`。

## 6. PMD 集成细节
- 配置文件：内置 `config/pmd/srs-pmd.xml`，只读加载。
- 输出解析：解析 `<pmd><file><violation beginline begincolumn rule ruleset ...>`。
- 规则映射：`ruleset/rule` → `rules/index.json` 中 `tool=PMD` 的 `tool_rule_id` → `SRS-* rule_id`。
- `tool_rule_id` 处理：保留 `ruleset/rule`，兼容仅规则名匹配。
- severity 映射：规则元数据优先；否则 PMD 1→CRITICAL、2→MAJOR、3→MAJOR、4→MINOR、5→INFO。
- 默认：`confidence=HIGH`，复杂规则可降为 `MEDIUM`，`detection_method=STATIC_ANALYSIS`。

## 7. SpotBugs 集成细节
- 编译产物依赖：需要 `target/classes` 或用户显式提供的 class 目录；M10 不编译。
- 输出解析：解析 `<BugInstance type category priority rank LongMessage><SourceLine ...>`。
- 规则映射：`type` → `rules/index.json` 中 `tool=SPOTBUGS` 的 `tool_rule_id` → `SRS-* rule_id`。
- `tool_rule_id` 处理：保留 Bug pattern，如 `NP_NULL_ON_SOME_PATH`。
- 默认关闭理由：依赖编译产物、约束禁止执行构建、误报较高、MVP 范围外。
- 无编译产物时：`status=SKIPPED`，`error_message=NO_COMPILED_ARTIFACTS`。

## 8. 工具输出适配为 ToolRun
| ToolRun 字段             | A6 `tool_runs` 字段 | 处理                              |
| ------------------------ | ------------------- | --------------------------------- |
| `tool`                   | `tool`              | 枚举：CHECKSTYLE、PMD、SPOTBUGS   |
| `version`                | `tool_version`      | 固定版本；版本不匹配记 FAILED     |
| `command`                | 无对应必填          | 内部审计字段，脱敏后记录          |
| `status`                 | `status`            | SUCCESS、FAILED、SKIPPED、TIMEOUT |
| `startedAt`              | `started_at`        | ISO-8601                          |
| `startedAt + durationMs` | `ended_at`          | 计算值                            |
| `durationMs`             | `duration_ms`       | 毫秒                              |
| `exitCode`               | `exit_code`         | 实际退出码；SKIPPED=0；TIMEOUT=-1 |
| `issueCount`             | `issues_count`      | 适配后候选数                      |
| `error`                  | `error_message`     | 失败原因、SKIPPED 原因            |
| `rawOutputPath`          | 无对应必填          | 临时目录路径，不落目标仓库        |

状态判定：
- SUCCESS：工具执行完成，退出码 0，输出解析成功。
- FAILED：未安装、版本不匹配、非零退出、解析失败。
- SKIPPED：`enabled=false`、M08 未选中该工具、SpotBugs 无编译产物。
- TIMEOUT：超过单工具超时或总预算。

## 9. 工具输出适配为 IssueCandidate
| IssueCandidate 字段 | 来源                 | 说明                                                         |
| ------------------- | -------------------- | ------------------------------------------------------------ |
| `rule_id`           | 映射表               | 工具原生 ID → `SRS-*`                                        |
| `severity`          | 规则元数据优先       | 否则工具默认映射，符合 A6 枚举                               |
| `confidence`        | 规则元数据优先       | 否则 HIGH/MEDIUM/LOW                                         |
| `detection_method`  | 固定                 | `STATIC_ANALYSIS`                                            |
| `file`              | 工具输出             | 相对目标仓库路径                                             |
| `line`              | 工具输出             | 缺省 0                                                       |
| `column`            | 工具输出             | 缺省 0                                                       |
| `evidence`          | 原始消息/片段        | 截断 4 KiB，脱敏                                             |
| `message`           | 规则元数据或工具消息 | 用户可读                                                     |
| `remediation`       | 规则元数据           | 缺省通用修复建议                                             |
| `sourceTool`        | 工具枚举             | CHECKSTYLE、PMD、SPOTBUGS                                    |
| `fingerprint`       | 计算                 | `SHA-256(tool|tool_rule_id|file|line|column|normalized_message)` |
| `rawEvidence`       | 原始节点             | JSON/字符串，供聚合与诊断                                    |
| `tool_rule_id`      | 工具原生 ID          | 内部字段，不直接进 A6 issue                                  |

E6 的 fingerprint 是工具侧原始指纹；E9 聚合时按统一算法重算，具体算法在 E9 决定。两者不强制相同，但需能相互映射。

未映射处理：
- MVP 阶段 `static.unmappedAsCustom` 写死 false；未映射默认丢弃，`metrics.unmapped_count++`，debug 日志记录。
- 不生成 IssueCandidate。
- 如需改为生成自定义问题，走 E2 配置清单评审，由 E3 增补。

## 10. 工具开关与配置
| 配置                        | 默认  | CLI                   | 语义                    |
| --------------------------- | ----- | --------------------- | ----------------------- |
| `static.checkstyle.enabled` | true  | `--enable-checkstyle` | 全局允许运行 Checkstyle |
| `static.pmd.enabled`        | true  | `--enable-pmd`        | 全局允许运行 PMD        |
| `static.spotbugs.enabled`   | false | `--enable-spotbugs`   | 全局允许运行 SpotBugs   |

与 M08 联动：
- M08 按 `tool` 与 `detection_method` 过滤规则，生成 `requiredTools`。
- M10 实际运行集合 = `{tool | enabled(tool)=true 且 requiredTools 包含 tool}`。
- `enabled=true` 但 M08 未选中：`SKIPPED`，`error_message=NO_RULES_SELECTED`。

与 strict 联动：
- strict=true：`requiredTools` 中 enabled=true 的工具 FAILED/TIMEOUT/解析失败 → 上层退出 5。
- enabled=false 不视为失败。
- 非 strict：记录失败并继续。

## 11. 超时与并发
| 项              | 默认值                               | 说明                                                         |
| --------------- | ------------------------------------ | ------------------------------------------------------------ |
| Checkstyle 超时 | 60s                                  | MVP 写死为 60s，不可配置；如需配置化，走 E2 配置清单评审，由 E3 增补 |
| PMD 超时        | 120s                                 | MVP 写死为 120s，不可配置；如需配置化，走 E2 配置清单评审，由 E3 增补 |
| SpotBugs 超时   | 180s                                 | MVP 写死为 180s，不可配置；如需配置化，走 E2 配置清单评审，由 E3 增补 |
| 总预算          | 600s                                 | MVP 写死为 600s，不可配置；如需配置化，走 E2 配置清单评审，由 E3 增补 |
| 并发            | 串行                                 | MVP 写死串行，不可配置；如需并行，走 E2 配置清单评审，由 E3 增补 |
| 并发限制        | Checkstyle/PMD 可并行                | 仅在并发开启时生效；MVP 串行下不适用                         |
| 内存            | Checkstyle 512m、PMD 1g、SpotBugs 2g | MVP 写死，不可配置；如需配置化，走 E2 配置清单评审，由 E3 增补 |

超时处理：杀进程树，`status=TIMEOUT`，`exit_code=-1`，保留已产生输出供诊断。

## 12. 只读保证
- 不修改目标仓库文件、权限、mtime。
- 不写 `.class`、`build`、`target`、缓存到目标仓库。
- 不执行 Maven/Gradle/npm 等构建命令。
- 临时输出、原始 XML、日志写入系统临时目录。
- SpotBugs 仅扫描已有 class 目录或用户显式提供路径；不存在则 SKIPPED。
- 不安装工具、不下载依赖、不训练模型。

## 13. 异常与降级
| 异常         | ToolRun 状态 | error_message         | 后续                              |
| ------------ | ------------ | --------------------- | --------------------------------- |
| 工具未安装   | FAILED       | TOOL_NOT_FOUND        | 继续其他工具；strict 退出 5       |
| 版本不匹配   | FAILED       | VERSION_MISMATCH      | 继续；strict 退出 5               |
| 工具超时     | TIMEOUT      | TIMEOUT               | 继续；strict 退出 5               |
| 工具非零退出 | FAILED       | EXIT_NONZERO          | 输出可解析仍 adapt；strict 退出 5 |
| 输出解析失败 | FAILED       | PARSE_ERROR           | candidates 空；strict 退出 5      |
| 总预算超限   | SKIPPED      | TOTAL_BUDGET_EXCEEDED | 剩余工具跳过                      |

## 14. 性能与规模
- 仅分析 `SourceBundle`，不扫描全仓。
- 沿用 E4 上限：变更文件 2000、单文件 1 MiB、总行 200k、总读取 100 MiB。
- 文件分批：每批 500 文件，降低单次工具内存。
- 总运行时间上限：600s；超限剩余工具 SKIPPED。
- Checkstyle/PMD 按文件列表运行；SpotBugs 默认关闭，避免编译与内存峰值。
- 缓存：工具版本、规则映射可缓存；审查结果不缓存。

## 15. 模块接口（对齐 E2 M10 契约）
- `runAll(SourceBundle, AppConfig) -> StaticAnalysisResult`
- `runTool(Tool, SourceBundle) -> ToolRun`
- `adapt(rawOutput) -> List<IssueCandidate>`
- 输入：SourceBundle、工具开关、工具配置、超时。
- 输出：StaticAnalysisResult、ToolRun 列表、IssueCandidate 列表。
- 依赖：Checkstyle、PMD、SpotBugs、M18。
- 可关闭/降级：可关闭；工具失败记录 FAILED 并继续；strict 可退出 5。

### 接口契约细节
1. 线程安全假设：M10 实例无状态，线程安全；`runTool` 可并发调用，但受并发上限与 SpotBugs 独占约束。
2. 幂等性：相同 `SourceBundle` 与 `AppConfig` 下，除时间戳、临时路径、耗时外输出相同；副作用仅临时目录文件与 M18 日志/指标。
3. 返回值可变性：`StaticAnalysisResult`、`ToolRun`、`IssueCandidate` 均为不可变对象；列表为只读视图。
4. 异常契约：三个接口都不抛异常，失败通过状态码与结果字段体现；运行时异常内部捕获并转为 FAILED。
5. 日志/指标注入点：通过 M18 记录；不在接口签名里传 Logger 参数。

## 16. 测试策略
- 单元：解析器用 golden XML；映射表覆盖 Checkstyle/PMD/SpotBugs。
- 状态机：SUCCESS、FAILED、SKIPPED、TIMEOUT 全覆盖。
- 契约：ToolRun/IssueCandidate 与 A6 Schema 对齐。
- 只读：运行前后目标仓库文件 hash/mtime 不变。
- 降级：未安装、版本不匹配、超时、非零退出、解析失败模拟。
- 集成：`examples/` 小型项目，不执行构建；SpotBugs 用预置 class。
- 性能：大文件列表、分批、总预算超限。
- 并发：串行默认、并行最大 2、SpotBugs 独占。

## 17. 未决问题
- SpotBugs 编译产物路径是否纳入 SourceBundle 正式字段
- PMD 7.4.0 规则集与内置配置兼容边界
- Checkstyle 自定义规则是否允许用户扩展
- SARIF 是否作为正式中间格式
- 工具二进制分发与版本锁定方式
- rawEvidence 脱敏规则与保留时长
- static.*.timeoutMs、parallel、static.unmappedAsCustom 等字段是否纳入配置；如需，走 E2 配置清单评审

## 18. 对 E7～E11 的影响
| 阶段                             | M10 给该阶段的输入                                           |
| -------------------------------- | ------------------------------------------------------------ |
| E7 JavaParser（M09）             | 不直接依赖 M10；两者均产出 IssueCandidate 供 E9 使用         |
| E8 LLM（M11）                    | 不直接依赖 M10；两者均产出 IssueCandidate 供 E9 使用         |
| E9 规则引擎（M12/M13）           | 消费 StaticAnalysisResult（ToolRun[] + IssueCandidate[]）；使用 sourceTool、fingerprint、rawEvidence 做去重与合并 |
| E10 报告（M14/M15/M16/M17）      | ToolRun[] 写入 A6 tool_runs；IssueCandidate 经聚合后写入 issue |
| E11 可观测/CLI/退出码（M18/M19） | 工具耗时、退出码、解析失败、未映射计数、超时与降级事件；strict 模式下工具失败致退出 5 |
