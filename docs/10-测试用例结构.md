# 10-测试用例结构

版本：v0.1  
阶段：C0  
状态：结构设计  
适用范围：Java 17+/Spring Boot 3.x，Maven/Gradle，git diff 或指定模块。  
约束：只读审查；不修改代码、不提交、不训练模型。  
兼容冻结：A3 目录结构、A4.2 索引最小字段、A5/A6 Schema、B1～B7 规则文件。

## 1. 设计原则

| 原则               | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| 冻结优先           | 严格沿用 A3、A4.2 已冻结的目录、ID、索引字段。               |
| 规则为中心         | `rule_id` 是规则、示例、测试用例的关联主键。                 |
| 一用例一规则一期望 | 一个测试用例只验证一个 `rule_id`，`expected` 只表达一次命中/不命中。 |
| 正反例分离         | `positive` 表示不应命中，`negative` 表示应命中。             |
| 机器可校验         | 测试用例以 JSON 为主，字段可映射到后续 JSON Schema。         |
| 输入可引用         | `input` 支持内联代码片段与测试夹具引用。                     |
| 最小可复现         | 示例与夹具应最小化，避免无关违规、外部依赖、敏感信息。       |
| 索引可重建         | `tests/cases/index.json`、`examples/index.json` 可由文件与元数据重建。 |
| 内容与结构分离     | C0 只定义结构；C1～C7 才填充具体规则、示例、用例内容。       |

## 2. examples/ 目录结构

```text
examples/
  index.json
  <一级分类码>/
    positive/
      SRS-<一级>-<二级>-<三位序号>_positive.<ext>
    negative/
      SRS-<一级>-<二级>-<三位序号>_negative.<ext>
```

示例：

```text
examples/
  index.json
  AR/
    positive/
      SRS-AR-01-001_positive.java
    negative/
      SRS-AR-01-001_negative.java
  CF/
    positive/
      SRS-CF-01-001_positive.java
    negative/
      SRS-CF-01-001_negative.java
```

`examples/index.json` 顶层最小字段：`version`、`generated_at`、`generated_by`、`count`、`items`。  
`items[]` 最小字段：`id`、`rule_id`、`category`、`subcategory`、`polarity`、`file`、`status`、`version`、`language`、`title`。

## 3. 正反例文件命名规则

| 类型    | 命名格式                                      | 示例                          |
| ------- | --------------------------------------------- | ----------------------------- |
| 正例    | `SRS-<一级>-<二级>-<三位序号>_positive.<ext>` | `SRS-AR-01-001_positive.java` |
| 反例    | `SRS-<一级>-<二级>-<三位序号>_negative.<ext>` | `SRS-AR-01-001_negative.java` |
| 示例 ID | 去掉扩展名后的文件名                          | `SRS-AR-01-001_positive`      |
| 规则 ID | 示例 ID 去掉 `_positive` / `_negative`        | `SRS-AR-01-001`               |

规则：

| 项           | 要求                                                         |
| ------------ | ------------------------------------------------------------ |
| 一级分类码   | 大写字母，与 `rule_id` 第二段一致。                          |
| 二级分类码   | 两位数字，与 `rule_id` 第三段一致。                          |
| 三位序号     | `001`～`999`，与 `rule_id` 第四段一致。                      |
| 扩展名       | 小写，如 `java`、`xml`、`yml`、`properties`、`gradle`、`kts`。 |
| 同规则正反例 | 基础 ID 必须相同，仅 `_positive` / `_negative` 不同。        |
| 唯一性       | 同一 `rule_id` 的 `positive`、`negative` 各一份；如需多示例，先变更 A3。 |

## 4. 正反例文件内容要求

| 项         | 正例要求                                             | 反例要求                                             |
| ---------- | ---------------------------------------------------- | ---------------------------------------------------- |
| 目标规则   | 不应命中目标 `rule_id`。                             | 应命中目标 `rule_id`。                               |
| 其他规则   | 尽量不命中其他规则。                                 | 尽量只命中目标规则。                                 |
| 最小化     | 仅保留验证目标规则所需内容。                         | 仅保留触发目标规则所需内容。                         |
| 可解析     | 应可被对应语言/配置解析器解析。                      | 应可被对应语言/配置解析器解析。                      |
| 依赖       | 不依赖网络、数据库、外部服务。                       | 不依赖网络、数据库、外部服务。                       |
| 编码       | UTF-8，LF 换行。                                     | UTF-8，LF 换行。                                     |
| 敏感信息   | 禁止包含密钥、令牌、真实凭据。                       | 禁止包含密钥、令牌、真实凭据。                       |
| 文件头注释 | 可选：示例 ID、`rule_id`、`polarity`、关联测试用例。 | 可选：示例 ID、`rule_id`、`polarity`、关联测试用例。 |
| 内容边界   | C0 不写具体代码。                                    | C0 不写具体代码。                                    |

## 5. tests/cases/ 目录结构

```text
tests/
  cases/
    index.json
    TC-<一级分类码>-<三位序号>.json
```

示例：

```text
tests/
  cases/
    index.json
    TC-AR-001.json
    TC-AR-002.json
```

命名规则：

| 项          | 要求                                                         |
| ----------- | ------------------------------------------------------------ |
| 文件名      | `TC-<一级分类码>-<三位序号>.json`                            |
| 测试用例 ID | `TC-<一级分类码>-<三位序号>`                                 |
| 一级分类码  | 与 `rule_id` 第二段一致。                                    |
| 三位序号    | `001`～`999`，按一级分类码独立编号。                         |
| 唯一性      | 全局唯一。                                                   |
| 索引        | `tests/cases/index.json` 顶层含 `version`、`generated_at`、`generated_by`、`count`、`items`。 |
| 索引 items  | 最小字段：`id`、`rule_id`、`category`、`file`、`status`、`version`、`title`、`tags`。 |

## 6. 测试用例 JSON 文件结构

### 6.1 顶层结构

```json
{
  "id": "TC-AR-001",
  "rule_id": "SRS-AR-01-001",
  "category": "AR",
  "subcategory": "01",
  "title": "",
  "description": "",
  "input": {},
  "expected": {},
  "positive_case": "",
  "negative_case": "",
  "tags": [],
  "version": "1.0.0",
  "status": "ACTIVE"
}
```

### 6.2 顶层字段定义

| 字段名          | 类型          | 必填 | 取值                                                         | 说明                                  |
| --------------- | ------------- | ---- | ------------------------------------------------------------ | ------------------------------------- |
| `id`            | string        | 是   | `^TC-(AR|CF|DI|WEB|DAO|SEC|CON|PERF|OBS|EXC|RES|TEST|BUILD|STYLE|NULL|I18N|MIG|CLOUD)-[0-9]{3}$` | 测试用例 ID，全局唯一。               |
| `rule_id`       | string        | 是   | `^SRS-(AR|CF|DI|WEB|DAO|SEC|CON|PERF|OBS|EXC|RES|TEST|BUILD|STYLE|NULL|I18N|MIG|CLOUD)-[0-9]{2}-[0-9]{3}$` | 关联规则 ID。                         |
| `category`      | string        | 是   | `^(AR|CF|DI|WEB|DAO|SEC|CON|PERF|OBS|EXC|RES|TEST|BUILD|STYLE|NULL|I18N|MIG|CLOUD)$` | 一级分类码，与 `rule_id` 第二段一致。 |
| `subcategory`   | string        | 是   | `^[0-9]{2}$`                                                 | 二级分类码，与 `rule_id` 第三段一致。 |
| `title`         | string        | 是   | 1～120 字符                                                  | 测试用例标题。                        |
| `description`   | string        | 是   | 1～500 字符                                                  | 测试目的与范围。                      |
| `input`         | object        | 是   | 见 6.3                                                       | 被测输入。                            |
| `expected`      | object        | 是   | 见 6.4                                                       | 期望结果。                            |
| `positive_case` | string        | 是   | 示例路径                                                     | 正例文件路径。                        |
| `negative_case` | string        | 是   | 示例路径                                                     | 反例文件路径。                        |
| `tags`          | array[string] | 是   | 0～n 个小写标签                                              | 检索与分组。                          |
| `version`       | string        | 是   | SemVer                                                       | 测试用例版本。                        |
| `status`        | string        | 是   | `DRAFT`、`REVIEW`、`ACTIVE`、`DEPRECATED`、`REMOVED`         | 测试用例状态。                        |

### 6.3 `input` 字段定义

| 字段名     | 类型   | 必填 | 取值                                                    | 说明                                        |
| ---------- | ------ | ---- | ------------------------------------------------------- | ------------------------------------------- |
| `type`     | string | 是   | `inline_code`、`fixture_ref`                            | 输入类型。                                  |
| `path`     | string | 条件 | `tests/fixtures/...`                                    | `type=fixture_ref` 时必填，相对仓库根路径。 |
| `content`  | string | 条件 | 代码或配置片段                                          | `type=inline_code` 时必填。                 |
| `language` | string | 否   | `java`、`xml`、`yaml`、`properties`、`gradle`、`kotlin` | 默认 `java`。                               |
| `encoding` | string | 否   | `utf-8`                                                 | 默认 `utf-8`。                              |

约束：

| 条件               | 要求                                      |
| ------------------ | ----------------------------------------- |
| `type=inline_code` | `content` 必填，`path` 为空或省略。       |
| `type=fixture_ref` | `path` 必填，`content` 为 `null` 或省略。 |
| `path`             | 必须位于 `tests/fixtures/` 下。           |

### 6.4 `expected` 字段定义

| 字段名             | 类型          | 必填 | 取值                     | 说明                                                         |
| ------------------ | ------------- | ---- | ------------------------ | ------------------------------------------------------------ |
| `triggered`        | boolean       | 是   | `true`、`false`          | `true` 表示应命中；`false` 表示不应命中。                    |
| `severity`         | string/null   | 条件 | 规则元数据 severity 枚举 | `triggered=true` 时必填；`triggered=false` 时为 `null`。取值必须使用 A2 severity 枚举，全大写：BLOCKER、CRITICAL、MAJOR、MINOR、INFO。 |
| `message_contains` | array[string] | 是   | 字符串数组               | `triggered=true` 时至少 1 项；`triggered=false` 时为 `[]`。应填写检测消息中的关键词或特征片段，便于回归断言；不要重复 rule_id。 |
| `location_hint`    | object/null   | 条件 | 见 6.5                   | `triggered=true` 时必填；`triggered=false` 时为 `null`。     |

`triggered` 语义：

| 值      | 语义                         | 常引用                       |
| ------- | ---------------------------- | ---------------------------- |
| `true`  | 输入应命中目标 `rule_id`。   | `negative_case` 或对应夹具。 |
| `false` | 输入不应命中目标 `rule_id`。 | `positive_case` 或对应夹具。 |

### 6.5 `expected.location_hint` 字段定义

| 字段名       | 类型        | 必填 | 取值             | 说明                      |
| ------------ | ----------- | ---- | ---------------- | ------------------------- |
| `file`       | string      | 条件 | 相对仓库根路径   | `triggered=true` 时必填。 |
| `line_start` | integer     | 否   | `>=1`            | 起始行。                  |
| `line_end`   | integer     | 否   | `>= line_start`  | 结束行。                  |
| `symbol`     | string/null | 否   | 类、方法、字段名 | 无法定位时为 `null`。     |

## 7. tests/fixtures/ 结构

```text
tests/
  fixtures/
    TC-<一级分类码>-<三位序号>/
      input.<ext>
      config.<ext>
      before.<ext>
      after.<ext>
    shared/
      <共享夹具文件>
```

| 项       | 要求                                                         |
| -------- | ------------------------------------------------------------ |
| 目录名   | 与测试用例 ID 一致，如 `TC-AR-001`。                         |
| 文件命名 | 推荐 `input.<ext>`、`config.<ext>`、`before.<ext>`、`after.<ext>`。 |
| 引用方式 | 测试用例 `input.path` 指向 `tests/fixtures/...`。            |
| 共享夹具 | 可放 `tests/fixtures/shared/`，但测试用例应显式引用。        |
| 索引     | 不强制建立 `fixtures/index.json`。                           |
| 内容边界 | C0 不写具体夹具内容。                                        |

## 8. tests/expected/ 结构

```text
tests/
  expected/
    TC-<一级分类码>-<三位序号>.json
    TC-<一级分类码>-<三位序号>.md
```

`TC-<一级分类码>-<三位序号>.json` 顶层字段：

| 字段名         | 类型   | 必填 | 取值           | 说明           |
| -------------- | ------ | ---- | -------------- | -------------- |
| `version`      | string | 是   | SemVer         | 期望文件版本。 |
| `generated_at` | string | 是   | ISO 8601       | 生成时间。     |
| `generated_by` | string | 是   | 工具或人工标识 | 生成者。       |
| `case_id`      | string | 是   | `TC-...`       | 测试用例 ID。  |
| `rule_id`      | string | 是   | `SRS-...`      | 关联规则 ID。  |
| `expected`     | object | 是   | 与 6.4 一致    | 期望结果。     |

`.md` 文件可选，用于 Markdown 报告快照。机器校验以 `.json` 为准。  
不得修改 `schema/review-report.schema.json`。

## 9. 规则、示例、测试用例三者关联方式

| 对象           | 主键/外键       | 关联字段                                        | 说明                                              |
| -------------- | --------------- | ----------------------------------------------- | ------------------------------------------------- |
| 规则           | `rule_id`       | `docs/rules/SRS-...`                            | 规则文件主键。                                    |
| 示例           | `id`            | `rule_id`                                       | 示例 ID = `rule_id` + `_positive` / `_negative`。 |
| 测试用例       | `id`            | `rule_id`                                       | 一个测试用例只关联一个规则。                      |
| 测试用例到示例 | `positive_case` | 示例路径                                        | 指向正例文件。                                    |
| 测试用例到示例 | `negative_case` | 示例路径                                        | 指向反例文件。                                    |
| 索引到规则     | `rule_id`       | `tests/cases/index.json`、`examples/index.json` | 通过 `rule_id` 聚合。                             |

关联约束：

| 约束     | 要求                                                         |
| -------- | ------------------------------------------------------------ |
| 规则存在 | `rule_id` 必须存在于 `docs/rules/`。                         |
| 示例存在 | `positive_case`、`negative_case` 必须存在。                  |
| 示例 ID  | 示例 ID 去掉极性后缀必须等于 `rule_id`。                     |
| 索引一致 | `examples/index.json.items[].rule_id` 与测试用例 `rule_id` 一致。 |
| 极性一致 | `positive_case` 对应 `polarity=positive`；`negative_case` 对应 `polarity=negative`。 |
| 语义一致 | `expected.triggered=true` 通常引用 `negative_case`；`expected.triggered=false` 通常引用 `positive_case`。 |
| 一对多   | 一个规则可有多个测试用例；一个测试用例只属于一个规则。       |

## 10. 测试用例与 examples/index.json、tests/cases/index.json 的对应关系

### 10.1 与 `tests/cases/index.json`

| `tests/cases/index.json.items[]` | 来源                     | 校验                      |
| -------------------------------- | ------------------------ | ------------------------- |
| `id`                             | 测试用例 JSON `id`       | 唯一。                    |
| `rule_id`                        | 测试用例 JSON `rule_id`  | 与规则、示例一致。        |
| `category`                       | 测试用例 JSON `category` | 与 `rule_id` 第二段一致。 |
| `file`                           | `tests/cases/<id>.json`  | 文件存在。                |
| `status`                         | 测试用例 JSON `status`   | 与完整 JSON 一致。        |
| `version`                        | 测试用例 JSON `version`  | 与完整 JSON 一致。        |
| `title`                          | 测试用例 JSON `title`    | 与完整 JSON 一致。        |
| `tags`                           | 测试用例 JSON `tags`     | 与完整 JSON 一致。        |

### 10.2 与 `examples/index.json`

| `examples/index.json.items[]` | 来源                     | 校验                                              |
| ----------------------------- | ------------------------ | ------------------------------------------------- |
| `id`                          | 示例文件名去扩展名       | 等于 `rule_id + _positive/_negative`。            |
| `rule_id`                     | 示例文件名基础           | 等于测试用例 JSON `rule_id`。                     |
| `category`                    | 目录名                   | 与 `rule_id` 第二段一致。                         |
| `subcategory`                 | 文件名段                 | 与 `rule_id` 第三段一致。                         |
| `polarity`                    | 目录 `positive/negative` | 与 `_positive/_negative` 一致。                   |
| `file`                        | 示例相对路径             | 等于测试用例 `positive_case` 或 `negative_case`。 |
| `status`                      | 示例元数据               | 与测试用例 `status` 同步。                        |
| `version`                     | 示例元数据               | 与测试用例 `version` 同步。                       |
| `language`                    | 扩展名或内容             | 与 `input.language` 兼容。                        |
| `title`                       | 示例标题                 | 可与测试用例 `title` 不同，但需可读。             |

## 12. 版本与变更规则

| 项           | 规则                                                         |
| ------------ | ------------------------------------------------------------ |
| 本文档版本   | v0.1，C0 结构设计。                                          |
| 结构冻结     | 冻结后版本升为 v1.0；后续变更需记录。                        |
