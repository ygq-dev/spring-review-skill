# docs/24-模块划分与接口契约.md

> 阶段：E2 模块划分与接口契约  
> 输入：E1 技术选型冻结、A6 报告结构、SKILL.md D1 工作流程、rules/examples/tests/schema 现有产出  
> 约束：只读审查；不修改代码、不提交、不训练模型；不改 A5/A6 Schema；不改 B1～B7 规则文件；不改 SKILL.md；模型调用可关闭；支持 DIFF/MODULE/FILES 三模式；支持无模型模式；报告必须符合 `schema/review-report.schema.json`。

## 1. 设计原则

1. **单向依赖，领域核心隔离外部工具**：CLI、配置、编排、规则、报告为核心；Git、JavaParser、Checkstyle、PMD、SpotBugs、LLM 以适配器接入。
2. **只读与无副作用**：所有模块不得修改源码、不得 git commit/push、不得训练模型；报告与日志是唯一持久化输出。
3. **默认可降级，关键路径 fail-fast**：模型、Markdown、SpotBugs、Checkstyle/PMD 可关闭或失败降级；配置、范围收集、规则加载、JSON 报告、Schema 校验失败为致命。
4. **契约对齐 A6**：跨模块传递的 `Issue`、`ReviewReport`、`ToolRun` 等以 A6 为唯一冻结结构，内部候选对象不得泄漏到最终报告。
5. **可观测内建**：每个模块产出结构化日志、耗时、状态；`tool_runs` 与 `metrics` 必须可追溯。
6. **适配器可替换**：`LlmClient` 抽象直接 HTTP + OpenAI 兼容；静态工具适配器统一输出 `ToolRun` 与 `IssueCandidate`。

## 3. 模块依赖图

```text
M01 CLI 入口
 ├─ M02 配置与密钥管理
 ├─ M19 退出码与 CLI 反馈
 └─ M03 审查编排器
      ├─ M04 范围解析与代码收集
      │    ├─ M05 Git Diff 收集器
      │    └─ M06 模块/文件收集器
      ├─ M07 规则加载器
      │    └─ M08 规则选择器
      ├─ M09 Java 源码解析
      ├─ M10 静态检查集成
      ├─ M12 规则匹配与语义分析
      │    ├─ M08
      │    ├─ M09
      │    ├─ M10
      │    └─ M11 模型调用层
      ├─ M13 问题汇总去重排序
      ├─ M14 JSON 报告生成
      │    └─ M17 报告校验
      ├─ M15 Markdown 报告生成
      ├─ M16 报告输出与归档
      └─ M18 可观测性与日志（被所有模块依赖）

外部依赖：JGit、JavaParser、Checkstyle、PMD、SpotBugs、Jackson、SnakeYAML、networknt、SLF4J/Logback、HTTP Client。
```

依赖方向原则：M01 → M03 → 领域模块；领域模块不反向依赖 CLI。M18 为横切依赖，所有模块可调用，但不依赖业务模块。

## 4. 逐模块接口契约

### M01 CLI 入口

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 解析 CLI 参数并启动一次只读审查。                            |
| 输入        | `String[] args`、环境变量、工作目录、stdin（可选）。         |
| 输出        | `ReviewRequest`、退出码、控制台反馈。                        |
| 对外接口    | `run(args, env) -> int`；`parse(args) -> ReviewRequest`；`printUsage() -> void`。 |
| 依赖方向    | 依赖 M02、M03、M19、M18；不被其他模块依赖。                  |
| 可关闭/降级 | 不可关闭；参数错误 fail-fast，退出码 2。                     |

### M02 配置与密钥管理

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 加载、合并、校验、脱敏配置与密钥。                           |
| 输入        | CLI 参数、环境变量、`.env.local`、`spring-review.yaml`、CI Secrets。 |
| 输出        | `AppConfig`、`SecretRef`、配置诊断。                         |
| 对外接口    | `load(ReviewRequest) -> AppConfig`；`resolveSecret(name) -> SecretRef`；`redact(AppConfig) -> AppConfigView`。 |
| 依赖方向    | 依赖 M18；被 M01、M03、M10、M11、M14、M16 依赖。             |
| 可关闭/降级 | 不可关闭；模型密钥缺失且未 offline 时，默认降级 offline 或按 strict 退出 2。 |

### M03 审查编排器

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 按 SKILL 8 步编排审查，控制步骤失败与降级。                  |
| 输入        | `ReviewRequest`、`AppConfig`。                               |
| 输出        | `ReviewResult`、`ReviewReport`、步骤状态。                   |
| 对外接口    | `review(ReviewRequest, AppConfig) -> ReviewResult`；`runStep(Step, Context) -> StepResult`；`abort(reason) -> ReviewResult`。 |
| 依赖方向    | 依赖 M04～M17、M18、M19；被 M01 依赖。                       |
| 可关闭/降级 | 不可关闭；可降级步骤按策略跳过并记录。                       |

### M04 范围解析与代码收集

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 统一解析审查范围并分派 DIFF/MODULE/FILES 收集。              |
| 输入        | `ReviewRequest`。                                            |
| 输出        | `ReviewScope`、`SourceBundle`、`DiffResult`。                |
| 对外接口    | `resolve(ReviewRequest) -> ReviewScope`；`collect(ReviewScope) -> SourceBundle`。 |
| 依赖方向    | 依赖 M05、M06、M18；被 M03、M08、M12 依赖。                  |
| 可关闭/降级 | 不可关闭；无文件或模式不支持时退出 3。                       |

### M05 Git Diff 收集器

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | DIFF 模式下用 JGit 收集变更文件与行范围。                    |
| 输入        | `repoRoot`、`baseRef`、`headRef`、include/exclude。          |
| 输出        | `DiffResult`、`ChangedFile`、`LineRange`、增量 `SourceUnit`。 |
| 对外接口    | `collectDiff(DiffRequest) -> DiffResult`；`changedLines(path) -> LineRange`；`changedFiles() -> List<ChangedFile>`。 |
| 依赖方向    | 依赖 JGit、M18；被 M04 依赖。                                |
| 可关闭/降级 | 非 DIFF 模式可关闭；DIFF 模式 Git 错误退出 3。               |

### M06 模块/文件收集器

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | MODULE/FILES 模式按模块或文件路径收集源码。                  |
| 输入        | `modulePaths`、`filePaths`、include/exclude、语言过滤。      |
| 输出        | `SourceBundle`、`SourceUnit` 列表。                          |
| 对外接口    | `collectModules(ModuleRequest) -> SourceBundle`；`collectFiles(FileRequest) -> SourceBundle`。 |
| 依赖方向    | 依赖文件系统、M18；被 M04 依赖。                             |
| 可关闭/降级 | 非 MODULE/FILES 可关闭；路径不存在退出 3。                   |

### M07 规则加载器

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 加载 `rules/*.yaml` 与 `rules/index.json`，并校验 rule-metadata。 |
| 输入        | `rulesDir`、`index.json`、`schema/rule-metadata.schema.json`。 |
| 输出        | `RuleSet`、加载诊断、规则版本。                              |
| 对外接口    | `load(rulesDir) -> RuleSet`；`reload() -> RuleSet`；`validateMetadata(rule) -> ValidationResult`。 |
| 依赖方向    | 依赖 Jackson YAML、SnakeYAML、M18；被 M08 依赖。             |
| 可关闭/降级 | 不可关闭；加载或元数据校验失败退出 4。                       |

### M08 规则选择器

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 按范围、文件类型、工具、检测方式过滤相关规则。               |
| 输入        | `RuleSet`、`ReviewScope`、`AppConfig`。                      |
| 输出        | `SelectedRules`、跳过原因。                                  |
| 对外接口    | `select(RuleSet, ReviewScope, AppConfig) -> SelectedRules`；`explain(ruleId) -> SelectionReason`。 |
| 依赖方向    | 依赖 M07、M18；被 M03、M12 依赖。                            |
| 可关闭/降级 | 不可关闭；无匹配规则时返回空集并警告。                       |

### M09 Java 源码解析

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 用 JavaParser 解析 Java 17+ 源码，产出 AST、包依赖、类/方法、行号。 |
| 输入        | `SourceUnit`、语言级别、解析配置。                           |
| 输出        | `ParsedSource`、`DependencyGraph`、`ParseError`。            |
| 对外接口    | `parse(SourceUnit) -> ParsedSource`；`analyzePackageDeps(ParsedSource) -> DependencyGraph`；`parseAll(SourceBundle) -> ParsedBundle`。 |
| 依赖方向    | 依赖 JavaParser、M18；被 M12 依赖。                          |
| 可关闭/降级 | 非 Java 可跳过；单文件解析失败记录并跳过，不致命。           |

### M10 静态检查集成

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 运行 Checkstyle/PMD/SpotBugs 并统一适配为 `ToolRun` 与 `IssueCandidate`。 |
| 输入        | `SourceBundle`、工具开关、工具配置、超时。                   |
| 输出        | `StaticAnalysisResult`、`ToolRun` 列表、`IssueCandidate` 列表。 |
| 对外接口    | `runAll(SourceBundle, AppConfig) -> StaticAnalysisResult`；`runTool(Tool, SourceBundle) -> ToolRun`；`adapt(rawOutput) -> List<IssueCandidate>`。 |
| 依赖方向    | 依赖 Checkstyle、PMD、SpotBugs、M18；被 M03、M12、M13 依赖。 |
| 可关闭/降级 | 可关闭；工具失败记录 `ToolRun.FAILED` 并继续，strict 模式可退出 5。 |

### M11 模型调用层

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 抽象 LLM 调用，支持 OpenAI 兼容多厂商，默认 DeepSeek。       |
| 输入        | `LlmRequest`、`AppConfig`、`SecretRef`。                     |
| 输出        | `LlmResponse`、usage、延迟、错误。                           |
| 对外接口    | `complete(LlmRequest) -> LlmResponse`；`health() -> LlmHealth`；`enabled() -> boolean`；`provider() -> String`。 |
| 依赖方向    | 依赖 HTTP Client、Jackson、M02、M18；被 M12 依赖。           |
| 可关闭/降级 | 可关闭；offline 时 `enabled=false`，语义规则跳过。           |

### M12 规则匹配与语义分析

| 项          | 内容                                                         |
| ----------- | ------------------------------------------------------------ |
| 职责        | 执行确定性规则、JavaParser 规则、LLM 语义规则，产出问题候选。 |
| 输入        | `SelectedRules`、`SourceBundle`、`ParsedSource`、`StaticAnalysisResult`、`LlmClient`。 |
| 输出        | `List<IssueCandidate>`、匹配统计、模型调用记录。             |
| 对外接口    | `match(SelectedRules, SourceBundle, ParsedSource, StaticAnalysisResult) -> List<IssueCandidate>`；`semanticReview(...) -> List<IssueCandidate>`；`confidenceOf(candidate) -> double`。 |
| 依赖方向    | 依赖 M08、M09、M10、M11、M18；被 M03、M13 依赖。             |
| 可关闭/降级 | LLM 部分可关闭；确定性规则不可关闭；模型失败时保留静态与确定性结果。 |

## 5. 模块与 SKILL.md 工作流程 8 步对应关系

| SKILL 步骤                | 负责模块           | 说明                                                    |
| ------------------------- | ------------------ | ------------------------------------------------------- |
| 1. 解析输入，确定审查范围 | M01、M02、M03、M04 | CLI 解析、配置合并、范围解析。                          |
| 2. 加载相关规则           | M07、M08           | 加载 RuleSet 并按 scope 选择。                          |
| 3. 收集待审代码           | M04、M05、M06      | DIFF/MODULE/FILES 分派收集。                            |
| 4. 运行静态检查           | M10                | Checkstyle/PMD/SpotBugs 适配为 ToolRun/IssueCandidate。 |
| 5. 规则匹配               | M09、M12、M11      | JavaParser、确定性规则、LLM 语义规则。                  |

## 9. 异常与降级策略

| 模块/场景                   | 失败行为                                     | 退出码/记录    |
| --------------------------- | -------------------------------------------- | -------------- |
| M01 参数错误                | 打印用法，不进入编排                         | 2              |
| M02 配置文件缺失            | 使用默认值 + 警告                            | 继续           |
| M02 模型密钥缺失            | 未显式 offline 时降级 offline；strict 则退出 | 2 或继续       |
| M03 编排步骤失败            | 可降级步骤跳过；关键步骤中止                 | 按子模块       |
| M04 模式不支持/无文件       | 中止                                         | 3              |
| M05 Git 错误                | DIFF 模式中止；非 DIFF 跳过                  | 3              |
| M06 路径不存在              | 中止                                         | 3              |
| M07 规则加载/元数据校验失败 | 中止                                         | 4              |
| M08 无匹配规则              | 空规则集 + 警告，继续                        | 继续           |
| M09 JavaParser 单文件失败   | 记录 `parseErrors`，跳过该文件               | 继续           |
| M10 工具未安装/超时/非零    | `ToolRun.FAILED`，继续；strict 升级          | 5（strict）    |
| M11 LLM 超时/限流/错误      | 重试后失败，语义规则跳过                     | 继续；strict 6 |
| M12 语义规则失败            | 保留静态与确定性结果                         | 继续           |
| M13 去重失败                | 降级简单排序                                 | 继续           |
| M14 JSON 生成失败           | 中止                                         | 5              |
| M15 Markdown 失败           | 记录，JSON 仍输出                            | 继续           |
| M16 写文件失败              | 中止                                         | 5              |
| M17 Schema 校验失败         | 中止                                         | 5              |
| M18 日志初始化失败          | 降级控制台                                   | 继续           |
| M19 未知异常                | 映射内部错误                                 | 6              |

退出码：0 成功；1 审查完成且达到 `exit.failOn`；2 CLI/配置；3 范围/代码收集；4 规则加载；5 报告/输出/校验或 strict 工具失败；6 内部错误或 strict 模型失败。

## 10. 未决问题

1. `exit.failOn` 默认阈值应为 CRITICAL 还是 HIGH。
2. Issue 去重指纹算法：`rule_id + file + line + column + message` 是否足够；语义问题行号漂移如何处理。
3. LLM 置信度校准与阈值，是否需要人工标注集。
4. Checkstyle/PMD/SpotBugs 输出解析格式与版本差异。
5. 规则选择策略：按包、模块、文件类型、标签还是显式 include/exclude。
6. AR 规则从 ARCHUNIT 改为 CUSTOM/HYBRID 后的验证用例覆盖。
7. 离线模式语义规则是跳过还是仅保留确定性规则。
8. `reports/latest` 原子更新与历史归档保留策略。
9. 模型并发限流、成本控制、重试退避策略。
10. `schema_version` 与规则 Schema 版本兼容策略。
11. 是否引入源码 hash、工具结果、模型结果缓存。
12. CI 中 Checkstyle/PMD/SpotBugs 安装与版本固定方式。
